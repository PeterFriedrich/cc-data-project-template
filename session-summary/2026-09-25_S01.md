## 3. Technical Learnings
- **Cloud and local sessions wake up differently.**
  - Cloud sessions (claude.ai/code) get platform instructions to schedule an hourly `send_later` check-in until the PR merges. A repo's `CLAUDE.md` rule, or its `.claude/skills/steward/SKILL.md` (read on PR events), overrides that.
  - A local CLI session, like the owner's edmonton tmux session on the Oracle box, has no `send_later` and no PR events. It costs nothing while idle unless it arms `/loop`, `CronCreate` or `ScheduleWakeup`. Its real cost is context growth, which `/handoff` then `/clear` fixes.
- **physics_sim already had the rule.** Its `CLAUDE.md` has "No scheduled PR check-ins" (its PR #9). The steward skill was not ported there, because it would only duplicate that line.
- **edmonton-tax-viz had no rule.** Its `CLAUDE.md` does not mention check-ins, `send_later`, triggers or wakeups (grepped a public clone on 2026-09-24).
- **`scripts/check_doc_citations.py` warnings on `SKILL.md`** are expected. It resolves bare filenames only as docs, so it warns and still exits 0.
- **The pre-push hook only works with `gh`,** and cloud sessions don't have it. So re-check that the PR merged before every push: I restarted this branch from `origin/master` after each merge.
