## 3. Technical Learnings
- ⚠️ **WebFetch returns a small model's summary, not the page.** For a real
  read, use `curl -sL` into the scratchpad and strip the tags with
  `python3.12 -I`. The owner asked "were you actually able to read the whole
  blog post?", and the honest answer was no until I did that.
- **`/code-review` was never used on this server before this session.** That
  was checked across repos, PR reviews and local transcripts. No project CI has
  a Claude review Action. Invoke it as `Skill code-review` with args
  `medium <PR#>`; it runs forked in the background.
- **Mutation-check every new guard test.** The first fence test in #37 was
  vacuous: a one-line block with no separator is never a table. Only reverting
  the fix showed it. My `sed` mutations with escaped regexes were silent
  no-ops, so use a python `str.replace` with a count assert.
- **Branch protection vs a workflow that pushes to master:** a required check
  blocks a `GITHUB_TOKEN` push. tax-viz uses `HEARTBEAT_TOKEN`, an admin PAT
  (`enforce_admins: false`, so admins bypass). A PAT push triggers workflows,
  so stage only paths the deploy ignores.
- **tax-viz has had no strandings since `.githooks/pre-push` (2026-08-09,
  35e1efb).** All 9 earlier ones were pushes after a merge. The owner
  sometimes squash-merges in the UI, so any stranded-commit scan must compare
  by patch (`git cherry`), not by `merge-base --is-ancestor`.
- **`edmonton-tax-viz` won't act on owner approval relayed by a peer for its
  CLAUDE.md.** It's correct to refuse. Send such edits to the owner, or tell
  the owner to confirm there.
- **GitHub Actions queued about 15 min on 2026-10-19 around 15:35 UTC**, across
  repos, with no posted incident. The repos are public, so it wasn't billing.
  It cleared by itself.
- `check_doc_citations.py` scans `README.md` and `TODO.md`, so run it after
  editing either one.
