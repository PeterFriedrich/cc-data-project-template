## 3. Technical Learnings
- ⚠️ **On this server's XFS root (`reflink=1`), uv 0.13 makes copy-on-write
  clones, not hard links.** Link count is 1, and `filefrag -v` shows
  `shared` extents. Blocks are still shared, but `du` counts every venv in
  full, so measure with `df -h /`. Editing a venv file can't corrupt the
  cache.
- uv is at `~/.local/bin/uv`, installed by `server` with
  `python3.12 -m pip install --user uv`. `server` also set
  `UV_PYTHON_DOWNLOADS=never` server-wide.
- `python -m ensurepip` has no `-q`, and it installs `pip3`/`pip3.12`, not
  `pip`. That's why the fallback calls `python -m pip`.
- Crontab greps miss venv users, because cron calls wrapper scripts:
  - permit-speed `scripts/weekly_archive.sh` runs Mon 05:00 UTC.
  - open-data-landscape `scripts/weekly_snapshot.sh` runs Fri 08:00 UTC.
  - server-ops `gdocs/backup.sh` runs daily at 10:00 UTC, and
    `gdocs/session_start.sh` runs as a SessionStart hook.
- `from google.cloud import storage` names its package in the imported name,
  which is why `imports()` emits `module.name` for from-imports, and
  `check()` dedupes per (file, line, package).
- The owner merges within minutes: #32 was merged before my #33 commit, and
  pre-push blocked the push. Always branch fresh from `origin/master` per PR.
- The built-in safety check refuses `rm -rf $VAR/...`. Use `"${S:?}"`.
