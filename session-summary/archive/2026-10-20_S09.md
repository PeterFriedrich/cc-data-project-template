## 3. Technical Learnings
- **Read other repos from GitHub, not from local refs.** Local `origin/master` refs in other clones are stale: civic-map's showed `e79c7b1` while GitHub had `5b48600`. Use `gh api repos/<r>/contents/…?ref=master`, or a `git clone --depth 1` into scratch. The 7 project masters were 177 MB; delete the clones after use.
- **Replay a project's copier update to test fidelity:**
  1. clone the project at its pre-update commit;
  2. point `_src_path` at `/home/opc/cc-data-project-template`;
  3. run `copier update --vcs-ref <commit>`.

  An absolute `_src_path` is needed, otherwise "Updating is only supported in git-tracked templates".
- **`git push --dry-run` runs `.githooks/pre-push`**, so a hook can be tested against a real merged branch without pushing.
- **Guard probes must look like CI:** `check_requirements.py` reads `git ls-files`, so an untracked probe file passes it.
- **`check_doc_citations.py`:**
  - a citation inside double quotes counts as a mention and isn't checked; that's how a findings doc can quote a banned form;
  - it resolves docs by basename, so `/home/opc/CLAUDE.md §"…"` would resolve against this repo's `CLAUDE.md`;
  - title matching searches the whole doc body, not only its headings.
- **`project-audit` tells the auditor to write `docs/AUDIT_<target>.md`,** and in the template that file would ship to projects (F7). Put the method in `docs/FINDINGS_*.md`, which is excluded.
- **Session answers can correct files I misread.** tax-viz corrected my "no port marker" claim. Mark peer answers "per `<session>`" until a file confirms them.
